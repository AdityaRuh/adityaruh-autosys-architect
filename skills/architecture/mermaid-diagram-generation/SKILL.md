# mermaid-diagram-generation

## When to Use

Use this skill when a proposed or existing system would be easier to explain with a Mermaid diagram. Typical cases include component overviews, service interactions, data flow, and dependency mapping.

## Procedure

1. Extract the confirmed architecture elements and relationships from the current context.
2. Choose a Mermaid diagram form that matches the need, such as a flowchart for system flow or dependency-oriented relationships for service mapping.
3. Generate a readable diagram with clear labels and only the components needed for the current discussion.
4. Keep the diagram aligned with the written recommendation and avoid introducing unstated components.
5. If uncertainty remains about a component or edge, label it as conditional in surrounding text instead of asserting it in the diagram.
6. Return Mermaid output in a form that works cleanly in the CLI workflow.

## Pitfalls

- Do not overload the diagram with every possible future service.
- Do not contradict the approved written recommendation.
- Do not invent hidden infrastructure or security layers that were not discussed.

## Verification

The skill succeeds when it produces a Mermaid diagram that accurately reflects the confirmed architecture and improves explanation clarity.
