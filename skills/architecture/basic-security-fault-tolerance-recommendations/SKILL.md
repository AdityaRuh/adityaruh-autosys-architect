# basic-security-fault-tolerance-recommendations

## When to Use

Use this skill when the user needs production-readiness guidance for security and resiliency in a proposed or existing architecture.

## Procedure

1. Review the confirmed architecture context and identify its main trust boundaries, critical dependencies, and likely failure scenarios.
2. Recommend baseline protections such as least-privilege integration posture, safe network boundaries, secret-handling avoidance in logs and memory, timeout and retry discipline, graceful degradation, and backup or recovery considerations where relevant.
3. Keep guidance focused on practical MVP-safe recommendations rather than full compliance programs.
4. Explain how each recommendation improves resiliency or reduces blast radius.
5. Align with the confirmed restrictions: read-only integrations by default, no destructive actions, no autonomous deployment or provisioning, and no unrestricted shell or system execution.

## Pitfalls

- Do not imply that baseline guidance is a complete security audit.
- Do not request or store secrets.
- Do not recommend production-changing actions as part of the default workflow.

## Verification

The skill succeeds when it returns a concise set of baseline security and fault-tolerance recommendations grounded in the confirmed architecture context and approved restrictions.
