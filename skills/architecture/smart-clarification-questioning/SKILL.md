# smart-clarification-questioning

## When to Use

Use this skill when key architecture constraints are missing or ambiguous. Typical triggers include incomplete requirements, unclear scale expectations, undefined reliability targets, missing budget guidance, or uncertainty about the preferred stack.

## Procedure

1. Review the current request and identify only the missing constraints that would materially change the architecture recommendation.
2. Ask a short set of focused questions covering confirmed gaps such as workload shape, expected traffic, latency sensitivity, reliability target, budget sensitivity, compliance or security needs, integration dependencies, and stack preferences.
3. Prefer high-leverage questions that reduce ambiguity quickly instead of asking for exhaustive specification detail.
4. Separate must-have constraints from nice-to-have preferences.
5. Once the user responds, summarize the clarified constraints before handing off to recommendation-oriented skills.
6. Do not ask questions about secrets, credentials, or deployment authority because those are out of scope for MVP.

## Pitfalls

- Do not ask broad brainstorming questions when a specific architectural decision is blocked by only one or two missing facts.
- Do not collect unnecessary sensitive information.
- Do not continue to the final design as if unanswered constraints were confirmed.

## Verification

The skill succeeds when it produces a concise question set that resolves the critical unknowns needed for a safe, practical architecture recommendation.
