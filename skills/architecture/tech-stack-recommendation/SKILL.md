# tech-stack-recommendation

## When to Use

Use this skill when the user asks for stack guidance, needs help selecting application or infrastructure technologies, or wants a stack recommendation as part of a new architecture design.

## Procedure

1. Gather confirmed product goals, team constraints, reliability needs, budget sensitivity, and explicit preferences.
2. Recommend a stack that fits the maturity stage and minimizes unnecessary complexity.
3. Cover the main layers relevant to the request, such as application runtime, data storage, messaging, caching, and hosting approach.
4. Explain why the stack fits the user’s constraints and what tradeoffs the choice introduces.
5. Stay cloud-neutral by default unless the user explicitly requests a provider-specific stack.
6. Avoid recommending tools that require secrets, destructive access, or unrestricted system execution for normal operation.

## Pitfalls

- Do not optimize for novelty over maintainability.
- Do not recommend a stack the user’s team is unlikely to operate successfully unless that tradeoff is explicit.
- Do not imply a stack choice is universally best outside the confirmed context.

## Verification

The skill succeeds when it returns a coherent stack recommendation with rationale that maps directly to confirmed goals and constraints.
